# 10. お寺コミュニティ広場（掲示板）（BRD）

| 項目 | 内容 |
| --- | --- |
| 機能ID | BRD-01 〜 BRD-05 |
| 関連テーブル | `board_topics`, `board_replies`（V7） |
| 関連資料 | [05_comment.md](05_comment.md)（投稿へのコメント） |

---

## 1. 概要

投稿に紐づかない話題を自由に話せる、スレッド形式の掲示板です。ユーザーがトピック（例: 「おすすめのお寺相談」「御朱印情報交換」）を作成し、他のユーザーが返信を書き込みます。投稿ごとの質問・感想は既存のコメント（[05_comment.md](05_comment.md)）を使います。

| ID | 内容 |
| --- | --- |
| BRD-01 | トピック一覧（最後に書き込みがあった順） |
| BRD-02 | トピックの作成 |
| BRD-03 | トピックの詳細と返信一覧（古い順） |
| BRD-04 | 返信の投稿 |
| BRD-05 | トピック・返信の削除 |

## 2. ユーザーストーリー

- 参拝者として、どのお寺に行くか迷ったときに、詳しい人に相談したい。
- 参拝者として、御朱印の受付時間や限定御朱印などの情報を交換したい。

## 3. 画面・UI

| 画面 | パス | 主な要素 |
| --- | --- | --- |
| コミュニティ広場 | `/community` | 説明文、トピック作成フォーム（ログイン時。未ログインは「ログインしてトピックを作成する」）、トピック一覧（タイトル・本文の先頭・作成者・返信数・最終更新日時、「もっと見る」） |
| トピック | `/community/topics/:id` | タイトル・本文・作成者・作成日時、作成者には削除ボタン、返信一覧（古い順、「さらに表示」）、返信フォーム（未ログインは「ログインして返信する」） |

- ヘッダーのメインナビゲーションに「コミュニティ広場」を置きます（狭い画面ではアイコンだけ。読み上げ名は常に「コミュニティ広場」）。
- 本文・返信はプレーンテキストとして表示し、改行を保持します（HTML は解釈しない）。
- 削除は確認ダイアログを出します。トピックを削除すると広場へ戻ります。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| GET | `/board-topics?cursor=&limit=20` | 不要 | トピック一覧 |
| POST | `/board-topics` | 必要 | トピック作成（201・`Location`） |
| GET | `/board-topics/{id}` | 不要 | トピック詳細 |
| DELETE | `/board-topics/{id}` | 必要 | トピック削除（作成者のみ。返信も削除） |
| GET | `/board-topics/{id}/replies?cursor=&limit=20` | 不要 | 返信一覧 |
| POST | `/board-topics/{id}/replies` | 必要 | 返信（201） |
| DELETE | `/board-replies/{id}` | 必要 | 返信の削除（返信の投稿者、またはトピックの作成者） |

### 4.1 トピック一覧 `GET /board-topics`

```json
{
  "items": [
    {
      "id": 12,
      "title": "紅葉の時期におすすめのお寺を教えてください",
      "bodyExcerpt": "11月中旬に京都へ行きます。…",
      "author": { "id": 2, "username": "kenta_camera", "displayName": "カメラ好きのケンタ", "avatarUrl": null },
      "replyCount": 3,
      "lastActivityAt": "2026-11-19T04:00:00Z",
      "createdAt": "2026-11-19T03:00:00Z"
    }
  ],
  "nextCursor": null
}
```

並び順は `lastActivityAt`（作成日時、または最新の返信の日時）の新しい順、同時刻は ID の降順です。返信があるとそのトピックが先頭に上がります。ページをめくる間に返信があると順番が動くため、画面では先に表示したトピックを重複して出さないようにしています。

### 4.2 トピック作成 `POST /board-topics`

リクエスト: `{ "title": "...", "body": "..." }`。レスポンスはトピック詳細（`body` を含み、`bodyExcerpt` はない）。

### 4.3 返信 `POST /board-topics/{id}/replies`

リクエスト: `{ "body": "..." }`。レスポンス: `{ "id": 301, "topicId": 12, "body": "...", "author": { ... }, "createdAt": "..." }`

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| タイトル | 1〜100文字（前後の空白を除く） |
| トピックの本文 | 1〜2000文字（前後の空白を除く） |
| 返信 | 1〜1000文字（前後の空白を除く） |
| 編集 | 提供しない（書き直したいときは削除して書き直す） |
| トピックの削除 | 作成者のみ。返信もまとめて削除（`ON DELETE CASCADE`） |
| 返信の削除 | 返信の投稿者、またはトピックの作成者（荒らし対策） |
| 最終書き込み日時 | 作成時は作成日時。返信すると進める（返信を削除しても戻さない） |
| 日時 | アプリの時計で記録し、DB の精度（マイクロ秒）に切り捨てる（カーソルがずれないようにする） |
| 削除連動 | ユーザーが削除されると、そのユーザーのトピック・返信も削除 |

## 6. 関連テーブル

| テーブル | 用途 |
| --- | --- |
| `board_topics` | トピック（作成者・タイトル・本文・最終書き込み日時） |
| `board_replies` | 返信（トピック・投稿者・本文） |

返信数は列に持たず、一覧のトピックの分を1回の SQL でまとめて数えます（`idx_board_replies_topic_id_created_at`）。

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | タイトル・本文・返信が空、または長すぎる |
| 400 | `INVALID_CURSOR` | カーソルの形式が不正 |
| 401 | `UNAUTHORIZED` | 未ログインで作成・返信・削除 |
| 403 | `FORBIDDEN` | 他人のトピックの削除、権限のない返信の削除 |
| 404 | `BOARD_TOPIC_NOT_FOUND` | 存在しないトピック（詳細・返信一覧・返信） |
| 404 | `BOARD_REPLY_NOT_FOUND` | 存在しない返信の削除 |

## 8. テスト観点

- 作成（空白の除去・Location）、未ログインでの閲覧と作成の拒否（`BoardIntegrationTest`）
- 一覧が最終書き込み順で、返信で先頭に上がること・返信数・カーソル・不正なカーソル
- 削除の権限（トピック: 作成者のみ、返信: 投稿者とトピックの作成者）と連鎖削除
- 最終書き込み日時が後退しないこと、本文の切り詰め（`BoardTopicTest`）
- 画面: ナビゲーション、一覧、作成と画面遷移、入力エラー、返信、削除ボタンの出し分け、HTML を文字列として表示（`board.test.tsx`）、E2E（`e2e/board.spec.ts`）

## 9. 補足・将来検討

- カテゴリ（相談・情報交換など）での絞り込み、トピックの検索は将来検討。
- 通報・管理者による削除は将来検討。
