# 08. スポットのステータス管理（STS）

| 項目 | 内容 |
| --- | --- |
| 機能ID | STS-01 〜 STS-06 |
| 関連テーブル | `user_spot_statuses` |
| 関連資料 | [要件定義書 3.8](../requirements.md#38-スポットのステータス管理status) |

---

## 1. 概要

スポットを自分用のリストで管理する機能です。どのスポット（自分の投稿でも他人の投稿でも）にも、次のどちらかのステータスを付けられます。

| ステータス | 値 | 意味 |
| --- | --- | --- |
| 訪問済み | `VISITED` | 実際に行ったことがある |
| 行きたい | `WANT_TO_GO` | いつか行きたい（旅行の候補） |

リストは **本人だけが見られる非公開リスト** です。他の人に見せる反応は「行ってみたい！」（[04_like.md](04_like.md)）を使います。

### 実装状況

| 項目 | 状況 |
| --- | --- |
| ステータスの設定・変更・解除、詳細・カードのステータス選択、マイリスト（マイページのタブ）・件数、「行った！」ボタン | 実装済み |
| 投稿作成時に自動で「訪問済み」を付けるオプション（STS-06） | 将来対応（優先度低のため見送り） |

## 2. ユーザーストーリー

- ユーザーとして、気になったスポットを「行きたい」リストに保存して、旅行の計画に使いたい。
- ユーザーとして、「行きたい」に入れていた場所に実際に行ったら「訪問済み」に変えたい。
- ユーザーとして、これまでに訪れた場所を一覧で振り返りたい。

## 3. 画面・UI

| 画面 | パス | 主な要素 |
| --- | --- | --- |
| スポット詳細・カード | `/spots/:id` など | ステータスの選択（マイリスト未登録 / 行きたい / 訪問済み を選ぶドロップダウン） |
| マイリスト | `/me?tab=want_to_go`（既定）・`/me?tab=visited` | マイページの「行きたい」「訪問済み」「行ってみたい！した投稿」のタブ、各リストのスポット一覧と件数 |

- ステータスの選択はキーボード・スマホでも扱いやすいよう、ブラウザ標準の `select` を使います。選んだ瞬間に表示を切り替え（楽観的更新）、失敗したら元に戻してトーストで知らせます。
- マイリストはマイページのタブに統合しました。選択中のタブは URL（`?tab=`）に持ち、左右キーでも切り替えられます。仕様当初のパス `/me/lists?status=want_to_go|visited` は該当するタブへ移動します。
- マイリストの各カードから、ステータスの変更・解除ができます（変更したスポットはリストを取り直したときに外れます）。カードの下に「〇月〇日に追加」「〇月〇日に訪問済みにしました」を表示します。
- 「行きたい」タブのカードには「行った！」ボタンを置き、ワンタップで「訪問済み」に変えられるようにします。
- 未ログイン時はドロップダウンの代わりに「マイリストに追加」ボタンを表示し、押すとログイン画面へ誘導します（ログイン後に元の画面へ戻る）。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| PUT | `/spots/{id}/status` | 必要 | ステータスを設定・変更 |
| DELETE | `/spots/{id}/status` | 必要 | ステータスを解除 |
| GET | `/me/spot-statuses?status=VISITED` | 必要 | マイリスト |
| GET | `/me/spot-statuses/summary` | 必要 | 各ステータスの件数 |

### 4.1 設定・変更 `PUT /spots/{id}/status`

リクエスト: `{ "status": "VISITED" }`

レスポンス `200 OK`:

```json
{ "spotId": 1024, "status": "VISITED", "visitedAt": "2026-11-11T03:00:00Z", "updatedAt": "2026-11-11T03:00:00Z" }
```

### 4.2 解除 `DELETE /spots/{id}/status`

レスポンス `204 No Content`（未設定の状態で呼んでも 204）。

### 4.3 マイリスト `GET /me/spot-statuses?status=WANT_TO_GO&cursor=&limit=20`

```json
{
  "items": [
    {
      "status": "WANT_TO_GO",
      "visitedAt": null,
      "updatedAt": "2026-11-10T12:00:00Z",
      "spot": { "id": 1024, "title": "朝の清水寺", "coverPhotoUrl": "...", "areaTags": [ "..." ] }
    }
  ],
  "nextCursor": null
}
```

並び順はステータスを更新した日時の新しい順です（同時刻はスポット ID の降順）。`status` は必須です。`spot` はスポット一覧（[02_spot.md 4.3](02_spot.md#43-一覧-get-spots)）と同じ形式です。`nextCursor` は「最後に返した行の更新日時とスポット ID」です。

スポットの詳細・一覧のレスポンスにも、閲覧者本人のステータスを `myStatus` として含めます（[02_spot.md](02_spot.md)）。

### 4.4 件数 `GET /me/spot-statuses/summary`

```json
{ "visited": 34, "wantToGo": 12 }
```

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 値 | `VISITED` または `WANT_TO_GO` のみ |
| 件数 | 1ユーザー1スポットにつき1ステータス（主キー `(user_id, spot_id)`）。同時に両方は付けられない |
| 設定方法 | `INSERT ... ON CONFLICT DO UPDATE`（UPSERT）。同じ値で再設定しても成功し、`visited_at` / `updated_at` は変えない（リストの並び順・訪問日時を保つ） |
| 日時 | アプリの時計で記録し、DB の精度（マイクロ秒）に切り捨てる（レスポンスの値と保存される値をそろえる） |
| 訪問日時 | `VISITED` にした日時を `visited_at` に記録。`WANT_TO_GO` に戻すと `visited_at` は消す |
| 対象 | 公開投稿、または自分の非公開投稿。他人の非公開投稿には付けられない（404） |
| 公開範囲 | 本人のみ閲覧可能。他人のリストを見る API は提供しない |
| 公開 → 非公開 | 他人の投稿が後から非公開になった場合、マイリスト・件数には含めない（データは残し、公開に戻れば再び表示する）。そのスポットのステータスの変更・解除は 404 |
| 削除連動 | スポットまたはユーザーが削除されると自動削除 |
| 自分の投稿 | 投稿作成時に自動で `VISITED` を付けるオプション（STS-06、優先度低。今回は見送り、将来対応） |

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `status` の値が不正・未指定 |
| 400 | `INVALID_CURSOR` | マイリストのカーソルの形式が不正 |
| 401 | `UNAUTHORIZED` | 未ログイン |
| 404 | `SPOT_NOT_FOUND` | 存在しない、または他人の非公開投稿 |

## 8. テスト観点

[品質チェック・テスト計画書 4.7](../qa_test_plan.md#47-ステータス管理status) を参照。特に以下を確認します。

- 「行きたい」→「訪問済み」→「行きたい」と変えたとき `visited_at` が正しく設定・消去されること
- 他人のマイリストが取得できないこと
- 後から非公開になった他人の投稿がマイリストに出ないこと
