# 08. スポットのステータス管理（STS）

| 項目 | 内容 |
| --- | --- |
| 機能ID | STS-01 〜 STS-06 |
| 関連テーブル | `user_spot_statuses` |
| 関連資料 | [要件定義書 3.8](../requirements.md#38-スポットのステータス管理status) |

---

## 1. 概要

スポットを自分用のリストで管理する機能です。どのスポット（自分の投稿でも他人の投稿でも）にも、次のどちらかのステータスを付けられます。

| ステータス | 値 | 意味 |
| --- | --- | --- |
| 訪問済み | `VISITED` | 実際に行ったことがある |
| 行きたい | `WANT_TO_GO` | いつか行きたい（旅行の候補） |

リストは **本人だけが見られる非公開リスト** です。他の人に見せる反応は「行ってみたい！」（[04_like.md](04_like.md)）を使います。

## 2. ユーザーストーリー

- ユーザーとして、気になったスポットを「行きたい」リストに保存して、旅行の計画に使いたい。
- ユーザーとして、「行きたい」に入れていた場所に実際に行ったら「訪問済み」に変えたい。
- ユーザーとして、これまでに訪れた場所を一覧で振り返りたい。

## 3. 画面・UI

| 画面 | パス | 主な要素 |
| --- | --- | --- |
| スポット詳細・カード | `/spots/:id` など | ステータスボタン（未設定 / 行きたい / 訪問済み を選ぶドロップダウン） |
| マイリスト | `/me/lists?status=want_to_go` | 「行きたい」「訪問済み」のタブ、各リストのスポット一覧と件数 |

- ステータスボタンは楽観的更新ですぐに表示を切り替えます。
- マイリストの各カードから、ステータスの変更・解除ができます。
- 「行きたい」タブのカードには「行った！」ボタンを置き、ワンタップで「訪問済み」に変えられるようにします。
- 未ログイン時はボタンを押すとログイン画面へ誘導します。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| PUT | `/spots/{id}/status` | 必要 | ステータスを設定・変更 |
| DELETE | `/spots/{id}/status` | 必要 | ステータスを解除 |
| GET | `/me/spot-statuses?status=VISITED` | 必要 | マイリスト |
| GET | `/me/spot-statuses/summary` | 必要 | 各ステータスの件数 |

### 4.1 設定・変更 `PUT /spots/{id}/status`

リクエスト: `{ "status": "VISITED" }`

レスポンス `200 OK`:

```json
{ "spotId": 1024, "status": "VISITED", "visitedAt": "2026-11-11T03:00:00Z", "updatedAt": "2026-11-11T03:00:00Z" }
```

### 4.2 解除 `DELETE /spots/{id}/status`

レスポンス `204 No Content`（未設定の状態で呼んでも 204）。

### 4.3 マイリスト `GET /me/spot-statuses?status=WANT_TO_GO&cursor=&limit=20`

```json
{
  "items": [
    {
      "status": "WANT_TO_GO",
      "visitedAt": null,
      "updatedAt": "2026-11-10T12:00:00Z",
      "spot": { "id": 1024, "title": "朝の清水寺", "coverPhotoUrl": "...", "areaTags": [ "..." ] }
    }
  ],
  "nextCursor": null
}
```

並び順はステータスを更新した日時の新しい順です。

### 4.4 件数 `GET /me/spot-statuses/summary`

```json
{ "visited": 34, "wantToGo": 12 }
```

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 値 | `VISITED` または `WANT_TO_GO` のみ |
| 件数 | 1ユーザー1スポットにつき1ステータス（主キー `(user_id, spot_id)`）。同時に両方は付けられない |
| 設定方法 | `INSERT ... ON CONFLICT DO UPDATE`（UPSERT）。同じ値で再設定しても成功する |
| 訪問日時 | `VISITED` にした日時を `visited_at` に記録。`WANT_TO_GO` に戻すと `visited_at` は消す |
| 対象 | 公開投稿、または自分の非公開投稿。他人の非公開投稿には付けられない（404） |
| 公開範囲 | 本人のみ閲覧可能。他人のリストを見る API は提供しない |
| 公開 → 非公開 | 他人の投稿が後から非公開になった場合、マイリストには表示しない（データは残す） |
| 削除連動 | スポットまたはユーザーが削除されると自動削除 |
| 自分の投稿 | 投稿作成時に自動で `VISITED` を付けるオプション（STS-06、優先度低） |

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `status` の値が不正 |
| 401 | `UNAUTHORIZED` | 未ログイン |
| 404 | `SPOT_NOT_FOUND` | 存在しない、または他人の非公開投稿 |

## 8. テスト観点

[品質チェック・テスト計画書 4.7](../qa_test_plan.md#47-ステータス管理status) を参照。特に以下を確認します。

- 「行きたい」→「訪問済み」→「行きたい」と変えたとき `visited_at` が正しく設定・消去されること
- 他人のマイリストが取得できないこと
- 後から非公開になった他人の投稿がマイリストに出ないこと
