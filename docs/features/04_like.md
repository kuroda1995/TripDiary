# 04. 行ってみたい！（いいね）（LIKE）

| 項目 | 内容 |
| --- | --- |
| 機能ID | LIKE-01 〜 LIKE-05 |
| 関連テーブル | `spot_likes` |
| 関連資料 | [要件定義書 3.4](../requirements.md#34-いいね行ってみたいlike) |

---

## 1. 概要

他のユーザーのスポットに「行ってみたい！」を付けられる、いいね機能です。件数はスポットに表示され、投稿者への反応として伝わります。

### 実装状況

| 項目 | 状況 |
| --- | --- |
| 付ける・外す・件数表示・自分の投稿（LIKE-01〜04） | 実装済み |
| 行ってみたい！した投稿の一覧（LIKE-05） | 実装済み（マイページ内の一覧。「行きたい」「訪問済み」と並べたタブ化はステータス管理機能で行う） |
| 行ってみたい！数順の並び替え | エリア検索機能（[07_area_search.md](07_area_search.md)）で追加 |

> **「行ってみたい！」と「行きたい」ステータスの違い**
>
> | | 行ってみたい！（本機能） | 行きたい（[08_spot_status.md](08_spot_status.md)） |
> | --- | --- | --- |
> | 目的 | 投稿者への公開リアクション | 自分用の旅行予定リスト |
> | 他の人から | 件数が見える | 見えない |
> | 併用 | 可能（両方付けられる） | 可能 |
>
> 画面ではアイコンと文言を明確に分けて表示します（例: 行ってみたい！= ハートアイコン、行きたい = ブックマークアイコン）。

## 2. ユーザーストーリー

- ユーザーとして、素敵なスポットに「行ってみたい！」を押して気持ちを伝えたい。
- 投稿者として、自分の投稿がどれだけ反応をもらえたか知りたい。
- ユーザーとして、「行ってみたい！」した投稿をあとで見返したい。

## 3. 画面・UI

- スポットカードと詳細画面に「行ってみたい！」ボタン（ハートアイコン）と件数を表示します。付けている状態は `aria-pressed` で読み上げにも伝えます。
- 押すと即座に表示を切り替え（楽観的更新）、API が失敗したら元に戻してトースト（[sonner](https://sonner.emilkowal.ski/)）でエラーを表示します。通信中は二重に押せないようにします。
- 成功したら、取得済みの詳細・一覧の件数も書き換えます（画面を移動しても表示がずれないようにする）。
- 未ログインで押した場合はログイン画面へ誘導し、ログイン後に元の画面へ戻します。
- マイページに「行ってみたい！した投稿」の一覧を表示します（LIKE-05）。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| PUT | `/spots/{id}/like` | 必要 | 行ってみたい！を付ける |
| DELETE | `/spots/{id}/like` | 必要 | 行ってみたい！を外す |
| GET | `/me/likes` | 必要 | 自分が行ってみたい！した投稿の一覧 |

PUT / DELETE のレスポンス `200 OK`:

```json
{ "spotId": 1024, "liked": true, "likeCount": 13 }
```

- PUT・DELETE とも **冪等** です（すでに付いている状態で PUT しても件数は増えません）。
- 件数・自分が付けたかどうか（`likeCount` / `likedByMe`）はスポットの一覧・詳細 API にも含まれます。一覧では、件数と自分が付けたかを **スポットの数に関係なく1回の SQL**（`GROUP BY spot_id` と `bool_or`）でまとめて取得します。

`GET /me/likes?cursor=&limit=20`: 付けた日時の新しい順。レスポンスはスポット一覧（[02_spot.md 4.3](02_spot.md#43-一覧-get-spots)）と同じ形式で、`nextCursor` は「最後のスポットに付けた日時とスポット ID」です。付けた後に非公開になった他人のスポットは含めません。

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 回数 | 1ユーザー1スポットにつき1回（`(user_id, spot_id)` の主キーで保証） |
| 自分の投稿 | 付けられる |
| 非公開投稿 | 本人以外は付けられない・外せない（404）。付けた後に非公開になった他人の投稿は「行ってみたい！した投稿」に出さない |
| 登録処理 | `INSERT ... ON CONFLICT DO NOTHING` で二重登録を防ぐ |
| 削除連動 | スポットまたはユーザーが削除されると自動削除 |
| 並び替え | 検索で「行ってみたい！数順」に使用（[07_area_search.md](07_area_search.md)） |

## 6. 関連テーブル

| テーブル | 用途 |
| --- | --- |
| `spot_likes` | 誰がどのスポットに付けたか（`user_id`, `spot_id`, `created_at`） |

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `INVALID_CURSOR` | 「行ってみたい！した投稿」のカーソルの形式が不正 |
| 401 | `UNAUTHORIZED` | 未ログイン |
| 404 | `SPOT_NOT_FOUND` | 存在しない、または他人の非公開投稿 |

## 8. テスト観点

- 付ける・外すで `likeCount` と `likedByMe` が正しく変わること
- 連続で PUT しても件数が1しか増えないこと
- 他人の非公開投稿には付けられないこと
- フロントエンドで API 失敗時に表示が元に戻ること

## 9. 補足・将来検討

- いいねされたときの通知は将来検討。
- `spot` パッケージが `like` パッケージに依存しないよう、件数の読み出しは `spot.SpotReactionReader`（インターフェース）を `like.LikeRepository` が実装する形にしています。コメント数を追加するときもこのインターフェースを拡張します。
- 件数の集計が重くなった場合は `spots.like_count` に件数を持たせる（[DB 設計書 3.3](../database_schema.md#33-spotsスポット投稿)）。
