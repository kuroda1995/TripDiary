# 09. お寺の評価・特徴タグ（TMPL）

## 1. 概要

お寺参拝の記録に特化した項目です。投稿に **4項目の5段階評価** と **お寺の特徴タグ** を付けられ、一覧・検索で特徴タグによる絞り込みができます。どちらも任意項目なので、お寺以外の旅行記録はこれまでどおり投稿できます。

| ID | 内容 |
| --- | --- |
| TMPL-01 | 投稿フォームで4項目を5段階で評価する（項目ごとに任意） |
| TMPL-02 | 投稿フォームで特徴タグを選ぶ（複数可・任意） |
| TMPL-03 | 詳細画面に評価と特徴タグ、一覧カードに評価の平均と特徴タグを表示する |
| TMPL-04 | 検索画面で特徴タグにより絞り込む（選んだタグをすべて持つ投稿） |

### 評価項目

| キー | 表示名 |
| --- | --- |
| `tranquility` | 静寂さ・雰囲気 |
| `beauty` | 庭園・建築の美しさ |
| `worship` | 御朱印・参拝の充実度 |
| `access` | アクセス・駐車場の停めやすさ |

### 特徴タグ

| 値 | 表示名 |
| --- | --- |
| `GOSHUIN` | 御朱印あり |
| `PARKING` | 駐車場あり |
| `GARDEN` | 庭園が美しい |
| `CULTURAL_PROPERTY` | 国宝・重要文化財 |
| `QUIET` | 静かに過ごせる |

## 2. ユーザーストーリー

- 参拝者として、行ったお寺の良さを項目ごとの点数で残し、次に行く人の参考にしたい。
- 参拝者として、「御朱印がもらえて駐車場があるお寺」のように条件を組み合わせて探したい。

## 3. 画面・UI

| 画面 | 主な要素 |
| --- | --- |
| 投稿・編集フォーム | 「お寺の評価（任意・5段階）」: 項目ごとに星5つ（ラジオボタン）と「未評価」。「お寺の特徴」: チェックボックス |
| スポット詳細 | エリアタグの下に特徴タグ。感想の下に「お寺の評価」（評価した項目だけ、星と点数） |
| 一覧カード | 特徴タグと「お寺の評価 ★★★★☆ 4.3」（評価した項目の平均。小数第1位） |
| 検索 | エリアの下に「お寺の特徴」のチェックボックス。URL は `?features=GOSHUIN,GARDEN` |

- 星はラジオボタンなので、キーボード（左右キー）でも点数を変えられます。読み上げは「5点」「5段階中4」。
- 特徴タグをクリックすると、そのタグで絞り込んだ検索結果を表示します。

## 4. API 仕様

新しいエンドポイントはありません。スポットの API（[02_spot.md](02_spot.md)）に項目を追加しています。

### 4.1 作成・更新 `POST /spots`・`PUT /spots/{id}`

```json
{
  "title": "雪の瑞龍寺",
  "...": "（既存の項目）",
  "ratings": { "tranquility": 5, "beauty": 5, "worship": 4, "access": 3 },
  "templeFeatures": ["GOSHUIN", "PARKING", "CULTURAL_PROPERTY"]
}
```

- `ratings` は省略・`null` 可（未評価）。各項目も `null` 可。
- `templeFeatures` は省略可（タグなし）。重複は1つにまとめ、表示順（上の表の順）で保存します。
- 更新は全項目置換のため、省略すると評価・タグは消えます。

### 4.2 詳細・一覧のレスポンス

スポット詳細と一覧の各要素に次を追加します。

| 項目 | 型 | 説明 |
| --- | --- | --- |
| `ratings` | object \| null | すべて未評価なら `null`。未評価の項目は `null` |
| `templeFeatures` | string[] | 表示順。なければ `[]` |

### 4.3 絞り込み `GET /spots?features=GOSHUIN,GARDEN`

- 指定したタグを **すべて** 持つ公開投稿に絞ります（AND）。エリア・キーワード・並び順と組み合わせられます（各条件も AND）。
- 未指定なら絞り込みません。

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 評価 | 各項目 1〜5 の整数、または `null`（未評価）。DB の CHECK 制約でも保証 |
| 特徴タグ | 上の5種類のみ。知らない値は 400。DB の CHECK 制約でも保証 |
| 件数 | 特徴タグは最大5個（全種類） |
| 公開範囲 | 絞り込みの対象は公開投稿のみ（他の検索と同じ） |

## 6. 関連テーブル

| テーブル | 用途 |
| --- | --- |
| `spots` | `rating_tranquility` / `rating_beauty` / `rating_worship` / `rating_access`（SMALLINT）、`temple_features`（VARCHAR(30)[]、GIN インデックス） |

特徴タグを別テーブルにしなかった理由は [database_schema.md 3.3](../database_schema.md#33-spotsスポット投稿) を参照してください。

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 評価が 1〜5 の範囲外（`details[].field` は `ratings.tranquility` など）、知らない特徴タグ（投稿・絞り込みとも） |

## 8. テスト観点

- 評価・タグを保存して詳細・一覧に返すこと、タグの並び替え・重複の除去（`TempleReviewIntegrationTest` / `TempleReviewTest`）
- 省略した投稿は `ratings = null`・`templeFeatures = []`、更新で置き換え・消去できること
- 範囲外の評価・知らないタグが 400 になること
- 絞り込みが AND 条件で、非公開投稿を含まず、エリア・キーワード・人気順・カーソルと組み合わせられること
- 画面: 入力・送信内容、編集時の初期値、詳細・カードの表示、検索画面の絞り込みと URL（`temple.test.tsx` / `searchParams.test.ts`）

## 9. 補足・将来検討

- お寺ごとの評価の平均（複数の投稿をまとめた評価）は、お寺をマスタとして持つ必要があるため将来検討。
