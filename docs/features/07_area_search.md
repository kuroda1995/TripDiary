## 1. 概要

スポットに付けたエリアタグ（例: 「京都」「沖縄」「台湾」）で投稿を絞り込む機能です。
エリアタグは運営側が用意するマスタデータで、「地方 → 都道府県」の親子階層を持ちます。親タグ（例: 「関西」）で検索すると、子タグ（「京都」「大阪」など）の投稿もまとめて表示します。

### 実装状況

| 項目 | 状況 |
| --- | --- |
| エリアタグ一覧・エリアタグ（親タグは子孫を含む）とキーワードでの絞り込み・新着順 / 人気順・検索画面・エリアタグからの検索 | 実装済み |
| ユーザーが自由にタグを作る機能（SRCH-06）・地図での範囲検索 | 将来対応（9章） |

### エリアタグの階層（初期データ）

```
北海道・東北 ─ 北海道 / 青森 / 岩手 / 宮城 / 秋田 / 山形 / 福島
関東         ─ 茨城 / 栃木 / 群馬 / 埼玉 / 千葉 / 東京 / 神奈川
中部         ─ 新潟 / 富山 / 石川 / 福井 / 山梨 / 長野 / 岐阜 / 静岡 / 愛知
関西         ─ 三重 / 滋賀 / 京都 / 大阪 / 兵庫 / 奈良 / 和歌山
中国・四国   ─ 鳥取 / 島根 / 岡山 / 広島 / 山口 / 徳島 / 香川 / 愛媛 / 高知
九州・沖縄   ─ 福岡 / 佐賀 / 長崎 / 熊本 / 大分 / 宮崎 / 鹿児島 / 沖縄
海外         ─ 韓国 / 台湾 / 中国本土 / 香港・マカオ / 東南アジア / ハワイ / グアム・サイパン / 北米 / ヨーロッパ / オセアニア / その他の海外
```

| 階層 | `level` | 例 |
| --- | --- | --- |
| 地方・海外 | 1 | 関西、海外 |
| 都道府県・国や地域 | 2 | 京都、台湾 |
| 市区町村など | 3 | （将来用） |

初期データ（地方6 + 海外、47都道府県 + 海外11エリア）は Flyway のマイグレーション（`V2__seed_area_tags.sql`）で投入しています。タグの追加・変更は新しいバージョンのマイグレーションで行います。スポットに付けられるのは level 2 のタグです（投稿画面では地方ごとに折りたたんで表示）。

## 2. ユーザーストーリー

- ユーザーとして、次の旅行先の「京都」の投稿だけを見たい。
- ユーザーとして、「関西」全体でおすすめの場所を探したい。
- ユーザーとして、人気のあるスポットから順に見たい。
- ユーザーとして、「温泉」などのキーワードでも探したい。

## 3. 画面・UI

| 画面 | パス | 主な要素 |
| --- | --- | --- |
| 検索 | `/search?areas=kyoto,osaka&q=温泉&sort=popular` | エリアタグ選択（階層表示・複数選択）、キーワード入力、並び替え、検索結果一覧 |

- ヘッダーの「探す」から開けます（未ログインでも利用可）。
- エリアタグは地方ごとに折りたたんで表示し、「〇〇全体」を選ぶとその地方全体を選択します。地方全体を選ぶと、その地方の個別の選択はまとめられ、子タグはチェック済み・変更不可で表示します。
- 選択中のタグはチップで表示し、× で外せます（「すべて外す」もあり）。
- 検索条件は URL のクエリに反映し、共有・再読み込み・ブラウザの戻る操作に対応します。URL のエリアは読みやすさのため **スラッグ**（`kyoto` など）で持ち、画面でエリアタグ一覧と照らして API 用の ID に変換します。存在しないスラッグは無視します。既定値（条件なし・新着順）は URL に出しません。
- エリア・並び順は変えた時点で、キーワードは「検索」ボタン（または Enter）で反映します。
- スポットカードや詳細画面のエリアタグをクリックすると、そのタグで検索した結果（`/search?areas=<slug>`）を表示します。
- 結果が0件の場合は「該当するスポットはありませんでした。条件を変えて検索してください。」と表示します。
- 人気順でページをめくる間に順位が動いて同じスポットが再び返っても、画面では先に出たものだけを表示します（5章）。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| GET | `/areas` | 不要 | エリアタグ一覧（階層構造） |
| GET | `/spots` | 不要 | スポット一覧・検索 |

### 4.1 エリアタグ一覧 `GET /areas`

```json
[
  {
    "id": 1, "name": "関西", "slug": "kansai", "level": 1,
    "children": [
      { "id": 2, "name": "京都", "slug": "kyoto", "level": 2, "children": [] },
      { "id": 3, "name": "大阪", "slug": "osaka", "level": 2, "children": [] }
    ]
  }
]
```

ほとんど変わらないデータのため、レスポンスに `Cache-Control: max-age=3600` を付け、画面側でも一度取得したら再取得しません。

### 4.2 スポット検索 `GET /spots`

| パラメータ | 型 | 説明 | 例 |
| --- | --- | --- | --- |
| `areaIds` | number[] | エリアタグ ID（複数はカンマ区切り、OR 条件） | `areaIds=2,3` |
| `q` | string | キーワード（タイトル・場所名の部分一致、最大100文字） | `q=温泉` |
| `sort` | string | `newest`（新着順・初期値）/ `popular`（行ってみたい！数順） | `sort=popular` |
| `cursor` | string | 次ページ取得用 | |
| `limit` | number | 取得件数（初期値20・最大50） | |

レスポンスは [02_spot.md 4.3](02_spot.md#43-一覧-get-spots) と同じ形式です。

- `areaIds` はカンマ区切り（`areaIds=2,3`）でも、繰り返し（`areaIds=2&areaIds=3`）でも指定できます。
- `q` は前後の空白を除き、空白だけなら絞り込みません。`%` `_` は文字そのものとして扱います。
- `nextCursor` は並び順ごとに形式が異なります（新着順: 投稿日時と ID、人気順: 行ってみたい！数・投稿日時・ID）。並び順を変えたら最初のページから取得し直してください。取り違えたカーソルは 400 `INVALID_CURSOR` です。
- 条件を省略した新着順は、新着一覧と同じ結果です。

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 複数タグ | OR 条件（いずれかのタグが付いた投稿） |
| 親タグ | 指定したタグとその子孫タグすべてを対象にする（マスタは数十件のため、全件を1回で読み込んでアプリ側で展開） |
| 指定数 | `areaIds` は最大10個 |
| 存在しないタグ | 400 `AREA_TAG_NOT_FOUND` |
| キーワード | タイトルと場所名を部分一致（大文字小文字を区別しない）。`pg_trgm` の GIN インデックスを利用 |
| 条件の組み合わせ | エリアタグとキーワードは AND 条件 |
| 対象 | 公開投稿のみ |
| 並び順 | `newest`: 投稿日時の降順 / `popular`: 行ってみたい！数の降順、同数なら投稿日時の降順（同時刻はいずれも ID の降順） |
| 人気順のページング | カーソル時点の件数で続きを取得するため、ページをめくる間に件数が変わると、順位が動いて重複・欠落が起こり得る（画面側で重複は表示しない。検索時点の結果を固定する仕組みは規模に対して重いため採用しない） |
| 重複 | 1つの投稿が複数の指定タグに当てはまっても1件として返す |

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | `sort` の値が不正、`areaIds` が11個以上、キーワードが長すぎる |
| 400 | `AREA_TAG_NOT_FOUND` | 存在しないエリアタグ ID |
| 400 | `INVALID_CURSOR` | カーソルの形式が不正、または並び順と合わない |

## 8. テスト観点

[品質チェック・テスト計画書 4.6](../qa_test_plan.md#46-エリアタグ検索search) を参照。特に以下を確認します。

- 親タグ指定で子タグの投稿が含まれること
- 複数タグに当てはまる投稿が重複しないこと
- 非公開投稿が検索結果に出ないこと
- 人気順のページングで重複・欠落がないこと
