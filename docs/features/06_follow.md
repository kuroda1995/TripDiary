# 06. フォロー / フォロワー（FLW）

| 項目 | 内容 |
| --- | --- |
| 機能ID | FLW-01 〜 FLW-05 |
| 関連テーブル | `follows` |

---

## 1. 概要

気になるユーザーをフォローし、その人の新しい投稿をタイムラインで追える機能です。フォローは承認不要の一方向の関係です（相手の許可なくフォローできます）。

### 実装状況

| 項目 | 状況 |
| --- | --- |
| プロフィール・フォロー / 解除・フォロー中 / フォロワー一覧・タイムライン | 実装済み |
| おすすめユーザー・フォロー通知・鍵アカウント・ブロック | 将来対応（9章） |

## 2. ユーザーストーリー

- ユーザーとして、好みの旅をしている人をフォローして、新しい投稿を見逃さないようにしたい。
- ユーザーとして、誰が自分をフォローしているか知りたい。
- ユーザーとして、興味がなくなった人のフォローを外したい。

## 3. 画面・UI

| 画面 | パス | 主な要素 |
| --- | --- | --- |
| ユーザープロフィール | `/users/:username` | アイコン、表示名、自己紹介、投稿数・フォロー数・フォロワー数、フォローボタン、投稿一覧 |
| フォロー中一覧 | `/users/:username/following` | ユーザーリスト（各行にフォローボタン） |
| フォロワー一覧 | `/users/:username/followers` | ユーザーリスト（各行にフォローボタン） |
| タイムライン | `/timeline` | フォロー中ユーザーの新着投稿（ログイン必須。ヘッダーにリンク） |

- フォローボタンは「フォローする」⇔「フォロー中」を切り替えます（楽観的更新）。失敗したら元に戻してトーストで知らせます。
- 「フォロー中」ボタンにカーソルを乗せる（キーボードで選ぶ）と「フォロー解除」と表示します。読み上げ名は押したときの動作（「@user をフォローする」「@user のフォローを解除」）にそろえます。
- 未ログインでフォローボタンを押すとログイン画面へ移動し、ログイン後に元の画面へ戻ります。
- 自分のプロフィールではフォローボタンの代わりに「プロフィール編集」ボタンを表示します。一覧の自分の行にはボタンを出しません。
- プロフィールのフォロー数・フォロワー数は各一覧へのリンクです。一覧の上部のタブで「フォロー中」「フォロワー」を切り替えます。
- タイムラインが空の場合は新着一覧への導線を表示します（おすすめユーザーは将来検討）。
- フォロー / 解除の後は、相手のプロフィールのフォロワー数と表示中の一覧のボタンをその場で更新し、自分のフォロー数・フォロー中一覧・タイムラインは次に開いたときに取り直します。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| GET | `/users/{username}` | 不要 | プロフィール（件数・自分がフォローしているか） |
| PUT | `/users/{username}/follow` | 必要 | フォローする |
| DELETE | `/users/{username}/follow` | 必要 | フォロー解除 |
| GET | `/users/{username}/following` | 不要 | フォロー中一覧 |
| GET | `/users/{username}/followers` | 不要 | フォロワー一覧 |
| GET | `/timeline` | 必要 | フォロー中ユーザーの新着投稿 |

### 4.1 プロフィール `GET /users/{username}`

```json
{
  "id": 42,
  "username": "taro_trip",
  "displayName": "旅するタロウ",
  "bio": "週末は温泉めぐり♨",
  "avatarUrl": null,
  "spotCount": 28,
  "followingCount": 15,
  "followerCount": 120,
  "followedByMe": true
}
```

### 4.2 フォロー `PUT /users/{username}/follow` / 解除 `DELETE /users/{username}/follow`

レスポンス `200 OK`:

```json
{ "username": "taro_trip", "following": true, "followerCount": 121 }
```

PUT・DELETE とも冪等です。`username` は登録時の表記で返します（URL のユーザー名は大文字・小文字を区別しません）。自分自身を指定すると PUT・DELETE とも 400 `CANNOT_FOLLOW_SELF` です。

### 4.3 一覧 `GET /users/{username}/followers?cursor=&limit=20`

```json
{
  "items": [
    { "id": 7, "username": "hanako", "displayName": "はなこ", "avatarUrl": null, "followedByMe": false }
  ],
  "nextCursor": null
}
```

並び順はフォローした日時の新しい順です（同時刻は相手のユーザー ID の降順）。フォロー中一覧 `GET /users/{username}/following` も同じ形式です。

- 未ログインでも閲覧できます（`followedByMe` は常に false）。`limit` は 1〜50 です。
- `nextCursor` は「最後に返した行のフォロー日時と相手のユーザー ID」を Base64URL でエンコードした文字列です（形式はスポット一覧と共通）。

### 4.4 タイムライン `GET /timeline?cursor=&limit=20`

レスポンスはスポット一覧（[02_spot.md 4.3](02_spot.md#43-一覧-get-spots)）と同じ形式です。カーソルはスポットの投稿日時と ID です。

### 4.5 パスの優先順位

`/users/me`（ログイン中の本人の API、[01_auth.md](01_auth.md)）はプロフィール `GET /users/{username}` より優先され、未ログインでは 401 です。ユーザー名は3文字以上のため `me` と衝突しません。

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 自分自身 | フォロー不可（API で 400、DB の CHECK 制約でも防止） |
| 重複 | 同じ相手を二重にフォローできない（主キー `(follower_id, followee_id)`） |
| 承認 | 不要（鍵アカウント機能は初期リリースでは提供しない） |
| タイムライン | フォロー中ユーザーの **公開** 投稿のみ、新着順。自分の投稿は含めない |
| 件数 | 投稿数は公開投稿のみ数える（本人が見る場合は非公開も含める） |
| 削除連動 | ユーザーが削除されるとフォロー関係も自動削除 |

## 6. 関連テーブル

| テーブル | 用途 |
| --- | --- |
| `follows` | フォローする側（`follower_id`）とされる側（`followee_id`） |
| `spots` | タイムラインの取得 |

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 400 | `CANNOT_FOLLOW_SELF` | 自分自身をフォロー・フォロー解除 |
| 400 | `INVALID_CURSOR` | 一覧・タイムラインのカーソルの形式が不正 |
| 401 | `UNAUTHORIZED` | 未ログインでフォロー・タイムライン取得 |
| 404 | `USER_NOT_FOUND` | 存在しないユーザー |
