# 11. 参考になった・行きたい・コミュニティ称号（CMTY）

| 項目 | 内容 |
| --- | --- |
| 機能ID | CMTY-01 〜 CMTY-04 |
| 関連テーブル | `spot_helpfuls`、`users.activity_count`（V8）、`user_spot_statuses`（既存） |
| 関連資料 | [04_like.md](04_like.md)（行ってみたい！）/ [08_spot_status.md](08_spot_status.md)（マイリスト） |

---

## 1. 概要

コミュニティに参加するきっかけを増やすための機能です。

| ID | 内容 |
| --- | --- |
| CMTY-01 | 投稿に「参考になった」を付ける・外す（件数を表示） |
| CMTY-02 | 投稿をワンタップで「行きたい」に保存する（ブックマーク） |
| CMTY-03 | 保存した投稿をマイページの「行きたい」タブで確認する |
| CMTY-04 | 投稿・コメント・掲示板の書き込みの合計に応じて、ユーザー名の横に称号を表示する |

### 既存機能との関係

| 反応 | 意味 | 実体 |
| --- | --- | --- |
| 行ってみたい！（既存） | 自分も行ってみたいと思った（公開の反応。人気順の並びに使う） | `spot_likes` |
| 参考になった（新規） | 記録が役に立った（公開の反応） | `spot_helpfuls` |
| 行きたい（新しいボタン） | 自分用のブックマーク（本人だけが見られる） | 既存のマイリストのステータス `WANT_TO_GO`（`user_spot_statuses`） |

「行きたい」は既存のマイリスト（[08_spot_status.md](08_spot_status.md)）をそのまま使い、詳細画面にワンタップで付け外しできるボタンを足しました。保存先・一覧（マイページの「行きたい」タブ）は既存と同じです。

### 称号

| 値 | 表示名 | 条件（投稿・コメント・掲示板のトピック・返信の合計） |
| --- | --- | --- |
| `BEGINNER` | 参拝ビギナー | 1件以上 |
| `PILGRIM` | 御朱印巡り人 | 3件以上 |
| `MASTER` | お寺マイスター | 5件以上 |

## 2. ユーザーストーリー

- 閲覧者として、役に立った参拝記録に「参考になった」を付けて、投稿者に感謝を伝えたい。
- 閲覧者として、気になるお寺をワンタップで保存し、あとでマイページから見返したい。
- 参加者として、書き込むほど称号が上がることで、続けて参加したくなりたい。

## 3. 画面・UI

| 画面 | 主な要素 |
| --- | --- |
| スポット詳細 | 「行ってみたい！」の隣に「参考になった（件数）」と「行きたい」ボタン。投稿者名の横に称号 |
| 一覧カード | 「参考になった（件数）」ボタン。投稿者名の横に称号 |
| コメント・掲示板 | 投稿者名の横に称号 |
| プロフィール | `@ユーザー名` の横に称号、件数に「コミュニティ活動」 |
| マイページ | 「行きたい」タブに保存したスポット（既存） |

- 「参考になった」は行ってみたい！と同じく、押した瞬間に切り替え（楽観的更新）、失敗したら元に戻してトーストで知らせます。未ログインならログイン画面へ。
- 「行きたい」ボタンは `aria-pressed` で状態を伝えます。すでに「訪問済み」のスポットには出しません（ボタンで訪問済みを消してしまわないため。変更はマイリストの選択から）。
- 称号にマウスを乗せると条件（「〜が5件以上」）を表示します。

## 4. API 仕様

| メソッド | パス | 認証 | 概要 |
| --- | --- | --- | --- |
| PUT | `/spots/{id}/helpful` | 必要 | 参考になったを付ける（冪等） |
| DELETE | `/spots/{id}/helpful` | 必要 | 外す（冪等） |

レスポンス: `{ "spotId": 1024, "helpful": true, "helpfulCount": 5 }`

既存のレスポンスへの追加:

| 対象 | 項目 | 説明 |
| --- | --- | --- |
| スポット詳細・一覧 | `helpfulCount` / `helpfulByMe` | 参考になったの件数・閲覧者が付けているか |
| ユーザー（`author` など全箇所） | `badge` | `BEGINNER` / `PILGRIM` / `MASTER`、0件は `null` |
| プロフィール | `activityCount` / `badge` | 活動数と称号 |

「行きたい」は既存の `PUT /spots/{id}/status`（`{"status":"WANT_TO_GO"}`）・`DELETE /spots/{id}/status` を使います。

## 5. 業務ルール・バリデーション

| 項目 | ルール |
| --- | --- |
| 参考になった | 1ユーザー1スポットにつき1回（主キー）。自分の投稿にも付けられる（行ってみたい！と同じ） |
| 対象 | 公開投稿、または自分の非公開投稿（他人の非公開は 404） |
| 活動数 | 投稿（非公開も含む）・コメント・掲示板のトピック・返信の件数の合計。DB のトリガーで増減させる |
| 連鎖削除 | 他人の投稿が削除されて自分のコメントが消えた場合も、活動数は減る |
| 反映のタイミング | 書き込んだ直後のレスポンスでは前の称号のことがある（次に取得したときに反映） |

## 6. 関連テーブル

| テーブル | 用途 |
| --- | --- |
| `spot_helpfuls` | 参考になった（ユーザー・スポット・付けた日時） |
| `users.activity_count` | 活動数（トリガー `trg_*_activity_count` で保つ。アプリからは書き込まない） |
| `user_spot_statuses` | 行きたい（既存） |

活動数を毎回数えず列で持つ理由は [database_schema.md 3.1](../database_schema.md#31-usersユーザー) を参照してください。

## 7. エラーコード

| HTTP | コード | 発生条件 |
| --- | --- | --- |
| 401 | `UNAUTHORIZED` | 未ログインで参考になったを付け外し |
| 404 | `SPOT_NOT_FOUND` | 存在しない、または他人の非公開投稿 |

## 8. テスト観点

- 参考になったの付け外し・冪等・行ってみたい！と独立していること・404/401・連鎖削除（`HelpfulIntegrationTest`）
- 称号の境界値（`CommunityBadgeTest`）、活動数が投稿・コメント・掲示板で増え、削除・連鎖削除で減ること、プロフィール編集で上書きされないこと、各レスポンスの `author.badge`（`CommunityBadgeIntegrationTest`）
- 画面: ボタンの楽観的更新・失敗時の巻き戻し・未ログイン、行きたいボタンとマイリストの連動・訪問済みでは非表示、称号の表示（`community.test.tsx`）、E2E（`e2e/community.spec.ts`）

## 9. 補足・将来検討

- 「参考になった」が多い順の並び替えは将来検討（必要になったら `like_count` と同じく列とトリガーで持つ）。
- 称号の段階・条件の追加は将来検討（`CommunityBadge` と画面の `BADGE_INFO` を合わせて変える）。
